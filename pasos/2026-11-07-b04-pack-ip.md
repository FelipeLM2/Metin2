# B04 — Parchear `SERVER_IP` en el pack y entrar sin `portproxy`

**Fecha:** 2026-11-07
**Máquinas:** CachyOS (host, pasos 1 y 3) y cliente Windows 10 (paso 2).
**Riesgo:** bajo. Se trabaja sobre una **copia** del pack; el original no se
toca. En el cliente se hace copia de los dos archivos antes de reemplazarlos.

## Objetivo

1. Copiar `root.eix`/`root.epk` a `~/metin2lab/work/b04` y pasar `verify`.
2. Extraer `serverinfo.py`, cambiar solo `SERVER_IP` a `10.10.10.10` y volver a
   meterlo con `m2pack set` (tipo 1, como el original).
3. Comprobar que el contenido nuevo es idéntico al original salvo esa línea.
4. Llevar los dos archivos al cliente en una ISO y un disco de retorno pequeño
   (para que la salida del cliente vuelva al host sin copiar a mano).
5. Quitar el `netsh interface portproxy` y entrar al juego con la IP directa.

Nada de esto usa unpackers de foro ni toca `C:\Metin2Dev`.

## Paso 1 — Preparar el pack parcheado y los medios (CachyOS)

Este bloque deja tres cosas en `~/metin2lab/work/b04`:

- `root.eix` / `root.epk` parcheados,
- `b04-pack.iso` (para el cliente),
- `retorno.img` (disco FAT16 de 16 MB para que el cliente devuelva su salida),

y escribe el registro completo en `~/metin2lab/work/b04/host.txt`.

```bash
set -u
cd ~/metin2-docs

W=~/metin2lab/work/b04
ISO_DIR="$W/iso"
mkdir -p "$W" "$ISO_DIR"

EIX=$(find ~/metin2lab/tmp4/Client -name root.eix -print -quit)
PACK=$(dirname "$EIX")

{
  echo "== 0. pack de origen =="
  echo "$PACK"
  ls -l "$PACK/root.eix" "$PACK/root.epk"
  sha256sum "$PACK/root.eix" "$PACK/root.epk"
  echo

  echo "== 1. copia de trabajo =="
  cp -f "$PACK/root.eix" "$W/root.eix"
  cp -f "$PACK/root.epk" "$W/root.epk"
  chmod u+w "$W/root.eix" "$W/root.epk"
  sha256sum "$W/root.eix" "$W/root.epk"
  echo

  echo "== 2. verify de la copia (antes de tocar) =="
  if ! python3 tools/m2pack/m2pack.py -p "$W" verify; then
    echo "ERROR: la copia no pasa verify; no se sigue"
    exit 1
  fi
  echo

  echo "== 3. serverinfo.py original =="
  python3 tools/m2pack/m2pack.py -p "$W" cat serverinfo.py -o "$W/serverinfo.orig.py"
  grep -n "SERVER_IP\|PORT_" "$W/serverinfo.orig.py"
  wc -c "$W/serverinfo.orig.py"
  echo

  echo "== 4. parche de SERVER_IP =="
  cp -f "$W/serverinfo.orig.py" "$W/serverinfo.py"
  sed -i 's/^SERVER_IP[[:space:]]*=.*/SERVER_IP = "10.10.10.10"/' "$W/serverinfo.py"
  grep -n '^SERVER_IP' "$W/serverinfo.py"
  diff -u "$W/serverinfo.orig.py" "$W/serverinfo.py"
  echo

  echo "== 5. m2pack set (tipo 1, LZO) =="
  python3 tools/m2pack/m2pack.py -p "$W" set serverinfo.py "$W/serverinfo.py"
  echo

  echo "== 6. releer serverinfo.py del pack =="
  python3 tools/m2pack/m2pack.py -p "$W" cat serverinfo.py -o "$W/serverinfo.new.py"
  diff -u "$W/serverinfo.orig.py" "$W/serverinfo.new.py"
  echo

  echo "== 7. entrada en el indice =="
  python3 tools/m2pack/m2pack.py -p "$W" ls | grep -i serverinfo
  ls -l "$W/root.eix" "$W/root.epk"
  echo

  echo "== 8. verify de la copia parcheada =="
  if ! python3 tools/m2pack/m2pack.py -p "$W" verify; then
    echo "ERROR: la copia parcheada no pasa verify; no se sigue"
    exit 1
  fi
  echo

  echo "== 9. ISO para el cliente =="
  cp -f "$W/root.eix" "$W/root.epk" "$ISO_DIR"/
  sha256sum "$W/root.eix" "$W/root.epk" > "$ISO_DIR/sha256.txt"
  cat "$ISO_DIR/sha256.txt"
  rm -f "$W/b04-pack.iso"
  xorriso -as mkisofs -o "$W/b04-pack.iso" -J -R -V B04PACK "$ISO_DIR"
  ls -l "$W/b04-pack.iso"
  echo

  echo "== 10. disco de retorno FAT16 =="
  if [ ! -f "$W/retorno.img" ]; then
    truncate -s 16M "$W/retorno.img"
    mkfs.vfat -F 16 -n B04RET "$W/retorno.img"
  fi
  ls -l "$W/retorno.img"
  file "$W/retorno.img"
} > "$W/host.txt" 2>&1

echo "salida: $W/host.txt"
tail -n 30 "$W/host.txt"
```

### Resultado esperado

- El `verify` de los pasos 2 y 8 termina en `RESULTADO: OK` (antes fallaba por
  el orden de los dos campos de tamaño; ya está corregido).
- El `diff` de los pasos 4 y 6 muestra **una sola línea**:
  `-SERVER_IP = "192.168.0.122"` / `+SERVER_IP = "10.10.10.10"`.
- `ls | grep serverinfo` sigue diciendo tipo `compress` y la posición
  `283136`; el tamaño del blob cambia, el hueco sigue en 768.
- `b04-pack.iso` ~0,5 MB y `retorno.img` 16 MB.

Si el `verify` inicial falla, **para** y publica `host.txt`: hay que corregir
`m2pack` antes de seguir.

## Paso 2 — Cliente Windows (VM aislada)

### 2.1 Apagar la VM y añadir los medios

1. Apaga Windows (`Stop-Computer`) y cierra la ventana de la VM.
2. En `virt-manager`: doble clic en la VM → botón **i** (detalles) → **Add
   Hardware**.
3. **Storage**, *Device type*: `CDROM device`, *Bus*: `SATA`, *Advanced* →
   *Storage format*: `raw`, selecciona
   `~/metin2lab/work/b04/b04-pack.iso`.
4. Otra vez **Add Hardware** → **Storage**, *Device type*: `Disk device`,
   *Bus*: `SATA`, *Storage format*: `raw`, selecciona
   `~/metin2lab/work/b04/retorno.img`. **No** marques "read-only".
5. Arranca la VM.

Si Windows pregunta si formatear el disco nuevo: **cancelar** y avisar. Debe
aparecer ya con la etiqueta `B04RET`.

### 2.2 Bloque único en PowerShell (como administrador)

Abre **PowerShell como administrador** (el `portproxy` y el registro lo
necesitan), copia el bloque entero y pégalo. Localiza solo la carpeta del
cliente, respalda los dos archivos, copia los nuevos, verifica los SHA256,
quita el `portproxy` y prueba la red. Al final te pide pulsar Enter: hazlo
**después** de entrar al juego.

```powershell
Start-Transcript -Path "$env:USERPROFILE\Desktop\b04-cliente.txt" -Force

$ErrorActionPreference = "Stop"

"== 0. packs encontrados =="
$found = @(Get-ChildItem -Path C:\ -Filter root.eix -Recurse -ErrorAction SilentlyContinue |
           Where-Object { Test-Path (Join-Path $_.DirectoryName "root.epk") })
$found | Select-Object -ExpandProperty FullName
if ($found.Count -ne 1) {
    throw "Hay $($found.Count) packs root.eix; ajusta `$pack a mano y repite"
}
$pack = $found[0].DirectoryName
$pack

"== 1. respaldo =="
$bak = "$env:USERPROFILE\metin2-backup\pack-orig"
New-Item -ItemType Directory -Force $bak | Out-Null
Copy-Item "$pack\root.eix" "$bak\root.eix.orig" -Force
Copy-Item "$pack\root.epk" "$bak\root.epk.orig" -Force
Get-FileHash "$bak\root.eix.orig", "$bak\root.epk.orig" -Algorithm SHA256 |
    Format-List Path, Hash

"== 2. medios =="
$iso = Get-Volume | Where-Object { $_.FileSystemLabel -eq "B04PACK" }
$ret = Get-Volume | Where-Object { $_.FileSystemLabel -eq "B04RET" }
$iso | Format-List DriveLetter, FileSystemLabel, Size
$ret | Format-List DriveLetter, FileSystemLabel, Size
$src = "$($iso.DriveLetter):"
$dst = "$($ret.DriveLetter):"

"== 3. copiar y comprobar =="
Copy-Item "$src\root.eix" "$pack\root.eix" -Force
Copy-Item "$src\root.epk" "$pack\root.epk" -Force
Get-Content "$src\sha256.txt"
Get-FileHash "$pack\root.eix", "$pack\root.epk" -Algorithm SHA256 |
    Format-List Path, Hash

"== 4. red =="
Get-NetIPAddress -AddressFamily IPv4 |
    Where-Object { $_.InterfaceAlias -notlike "*Loopback*" } |
    Format-Table InterfaceAlias, IPAddress -Auto
Test-NetConnection 10.10.10.10 -Port 11000
Test-NetConnection 10.10.10.10 -Port 13000

"== 5. portproxy =="
netsh interface portproxy show all
netsh interface portproxy reset
netsh interface portproxy show all

"== 6. abrir el cliente y entrar al juego =="
"Lanza el cliente a mano y entra con la cuenta test."
Read-Host "Cuando estes dentro del juego, pulsa Enter"

Stop-Transcript

"== 7. copiar la salida al disco de retorno =="
Copy-Item "$env:USERPROFILE\Desktop\b04-cliente.txt" "$dst\b04-cliente.txt" -Force
Get-ChildItem "$dst"

"Ahora apaga la VM:  Stop-Computer"
```

### Resultado esperado

- El `Get-Content` de `sha256.txt` y los dos `Get-FileHash` coinciden
  (mismos hashes que en el paso 1 de CachyOS).
- `Test-NetConnection` a **11000** y **13000** dice `TcpTestSucceeded : True`.
- `netsh interface portproxy show all` sale vacío después del `reset`.
- El cliente entra al juego y se puede mover con la cuenta `test`.
- `b04-cliente.txt` aparece en el disco `B04RET`.

## Paso 3 — Recoger la salida y publicar (CachyOS)

Apaga la VM del todo y ejecuta:

```bash
cd ~/metin2-docs

W=~/metin2lab/work/b04
MNT=/mnt/b04ret
sudo mkdir -p "$MNT"
if ! sudo mount -o ro,loop "$W/retorno.img" "$MNT" 2>/dev/null; then

  sudo mount -o ro,loop "$W/retorno.img" "$MNT"
fi

{
  echo "== 0. host: preparacion y parche =="
  cat "$W/host.txt"
  echo
  echo "== 11. cliente Windows: transcripcion =="

} > salidas/2026-11-07-b04-pack-ip.txt

sudo umount "$MNT"
wc -l salidas/2026-11-07-b04-pack-ip.txt
```

Si el montaje falla por el flag "sucio" de Windows, `fsck.vfat -a` lo limpia
(se ejecuta sobre el archivo imagen, no sobre el montaje).

Publicar:

```bash

git diff --stat
```

Avisa: «B04 subido».

## Si algo falla

| Síntoma | Qué hacer |
|---|---|
| `verify` inicial falla | Para. Publica `host.txt`: hay otro detalle del formato por corregir. |
| El `diff` muestra más de una línea | No sigas: revisa que `sed` solo tocó `^SERVER_IP` (no `SERVER_IP_TEST`). |
| `m2pack set` dice que no cabe | No debería: el hueco es 768 y el blob nuevo ronda 600. Publica la salida. |
| Windows pide formatear `B04RET` | Cancela. Windows no debe tocar el disco; avisa y seguimos con otra vía. |
| El cliente no arranca o no carga el mundo | Restaura `root.eix.orig`/`root.epk.orig` desde `metin2-backup\pack-orig` y avisa: puede que el cliente no acepte el índice plano y haya que escribirlo cifrado. |
| `Test-NetConnection` falla al 11000 | Comprueba `ipconfig`: el cliente debe tener `10.10.10.20/24` sin gateway. |

## Qué hará el agente con la salida

1. Confirmar `verify` OK antes y después y que el `diff` es de una sola línea.
2. Confirmar que el cliente entra sin `portproxy` y con la IP nueva.
3. Cerrar la Fase B, actualizar el plan y dejar el cliente preparado para la
