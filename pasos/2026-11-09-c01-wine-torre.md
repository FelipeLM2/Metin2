# C01 — Cliente Wine + DXVK en la torre, sin Internet

**Fecha:** 2026-11-09
**Máquina:** CachyOS (torre, host) y la VM FreeBSD (servidor).
**Riesgo:** medio. Se ejecuta un `.exe` de terceros. Se contiene con una jaula
de red sin salida y sin la unidad `Z:`; **no se ejecuta como root**.

## Qué vamos a montar

```
CachyOS (torre)
│
├── VM FreeBSD  10.10.10.10 ──── virbr-lab ──── [jaula de red] 10.10.10.20
│                                                   └── Wine + DXVK + cliente
│
└── tu escritorio, Internet, tus archivos…  (la jaula NO los ve por red)
```

Decisiones tomadas (2026-11-09):

- **Mismo usuario** (`deadivine`): la primera prueba valida si el cliente
  arranca. Si funciona, se endurece con un usuario `metin2` aparte (C01-bis).
- **`ip netns`**: jaula del kernel, sin binarios SUID. Solo `10.10.10.20/32` y
  una ruta a `10.10.10.10/32`; sin puerta de enlace, sin DNS, sin IPv6.
- **Sin `Z:`**: Wine no mapea `/`. El cliente vive en `C:\Games\Metin2`.
- **Internet solo en la preparación**: DXVK se descarga una vez. El juego se
  ejecuta siempre dentro de la jaula, que no tiene salida.
- **VM Windows apagada**: libera `10.10.10.20` y RAM. No se borra; queda de
  respaldo.
- **Monitor en la GTX 1650**: DXVK usará la GPU directamente.

## Regla de oro

Si algún script imprime **`PELIGRO`** (salida a Internet, resolución de
nombres), **para y avisa**. No sigas por tu cuenta.

## Antes de empezar

1. Actualiza el repo:

```bash
cd ~/metin2-docs
git pull
```

2. **Apaga la VM Windows** desde `virt-manager` (la IP `.20` la usará la
   jaula). Deja **encendida** la VM FreeBSD.
3. Comprueba el servidor y los archivos de partida:

```bash
ssh root@10.10.10.10 hostname
ls -l ~/metin2lab/tmp4/Client/Client
ls -l ~/metin2lab/work/b04/root.eix ~/metin2lab/work/b04/root.epk
```

Debe responder el hostname de FreeBSD y los tamaños deben ser **17292** y
**520704**.

4. Si el diagnóstico (fase 0) dice que falta algo, instala antes de seguir:

```bash
sudo pacman -S --needed wine winetricks vulkan-tools lib32-vulkan-icd-loader lib32-nvidia-utils
```

> Si usas el driver libre (`nouveau`), cambia `lib32-nvidia-utils` por
> `lib32-mesa`. Si `pacman` no encuentra `wine`, habilita el repositorio
> `multilib` en `/etc/pacman.conf`.

## Fase 0 — Diagnóstico (solo lectura)

```bash
cd ~/metin2-docs
bash tools/c01/00-diagnostico.sh 2>&1 | tee salidas/2026-11-09-c01-00-diagnostico.txt
```

Mira la salida y comprueba:

| Qué | Debe decir |
|---|---|
| `vulkaninfo` | `deviceName = NVIDIA GeForce GTX 1650` |
| `nvidia-smi` | la 1650 y la versión del driver |
| `/usr/lib32/libvulkan.so*` | existe (32 bits) |
| `wine --version` | una versión (ej. `wine-10.x`) |
| Cliente | una carpeta con `.exe` en la raíz |
| Anti-cheat | vacío (nada de `hackshield`, `xigncode`, …) |
| `root.eix` / `root.epk` | `17292` / `520704` y los hashes `a3d02f…` / `0396d0…` |
| `virbr-lab` | existe con `10.10.10.1/24` |
| SSH | responde `hostname` |

**PARADA** si:

- no aparece Vulkan o solo aparece en el HD 630 (la iGPU);
- hay archivos de anti-cheat en el cliente;
- no está `wine` o no existe la carpeta del cliente;
- los tamaños del pack no son 17292 / 520704.

En cualquiera de esos casos, publica la salida y avisa antes de continuar.

## Fase 1 — Prefijo, cliente y pack

```bash
cd ~/metin2-docs
bash tools/c01/10-prefix.sh 2>&1 | tee salidas/2026-11-09-c01-01-prefijo.txt
```

Qué hace:

1. Crea `~/metin2lab/wine/prefix` como prefijo **win32** (el cliente es de 32
   bits).
2. Borra de `dosdevices/` todas las unidades menos `C:`. En particular `Z:`,
   que apunta a `/`.
3. Copia el cliente de `~/metin2lab/tmp4/Client/Client` a
   `C:\Games\Metin2`.
4. Sustituye el pack por el parcheado de `~/metin2lab/work/b04`.

**Resultado esperado:** en `dosdevices` solo aparece `c:`; el pack del cliente
mide **17292** / **520704** y los hashes son los de B07
(`a3d02f…` / `0396d0…`).

**PARADA** si los hashes no coinciden o si `dosdevices` sigue teniendo `z:`.

## Fase 2 — DXVK (única descarga)

```bash
cd ~/metin2-docs
bash tools/c01/15-dxvk.sh 2>&1 | tee salidas/2026-11-09-c01-02-dxvk.txt
```

Qué hace: busca la última versión de DXVK en GitHub, la descarga, y copia
`x32/d3d9.dll` y `x32/dxgi.dll` dentro del prefijo. Es el **único** momento del
paso en que se usa Internet.

**Resultado esperado:** las dos DLL en
`~/metin2lab/wine/prefix/drive_c/windows/system32/` con su SHA256.

Si la API de GitHub falla, fija la URL a mano:

```bash
DXVK_URL=https://github.com/doitsujin/dxvk/releases/download/v2.7.1/dxvk-2.7.1.tar.gz \
  bash tools/c01/15-dxvk.sh
```

(Usa la versión que exista; el script acepta cualquier `DXVK_URL`.)

## Fase 3 — Jaula de red

```bash
cd ~/metin2-docs
bash tools/c01/20-netns-up.sh 2>&1 | tee salidas/2026-11-09-c01-03-jaula.txt
```

Qué hace: crea el *network namespace* `metin2lab`, le cuelga una `veth` del
puente `virbr-lab`, le pone `10.10.10.20/32` y **una sola ruta** a
`10.10.10.10/32`. Sin puerta de enlace, sin DNS y sin IPv6.

**Resultado esperado:**

- `ip route` muestra **solo** `10.10.10.10 dev veth-m2` (nada de `default`).
- `ping 10.10.10.10` responde.
- `curl https://1.1.1.1` **falla** y el script dice `OK: sin salida a Internet`.

**PARADA** si aparece `PELIGRO` o si `ip route` muestra un `default`.

## Fase 4 — Lanzar el cliente y comprobar

### Terminal A — el juego

```bash
cd ~/metin2-docs
bash tools/c01/30-run-client.sh
```

Se abrirá la ventana del cliente. En la esquina verás el **HUD de DXVK** con
FPS, carga de GPU y el nombre del dispositivo. Debe decir **GTX 1650**. Elige
la **primera** entrada de servidor (`Metin2`), **no** `Test` (esa sigue
apuntando a `127.0.0.1` y falla a propósito). Entra al juego y quédate dentro
unos 30 segundos.

### Terminal B — el aislamiento

Con el juego abierto, en otra terminal:

```bash
cd ~/metin2-docs
bash tools/c01/35-check-isolation.sh 2>&1 | tee salidas/2026-11-09-c01-04-aislamiento.txt
```

Y comprueba que la GPU está trabajando:

```bash
nvidia-smi
```

Debe aparecer un proceso del cliente (`metin2client.exe` o `wine`) usando
memoria de la 1650.

**Resultado esperado:**

- `35` dice `OK: sin salida a Internet` y `OK: sin DNS`.
- `ss` muestra conexiones **solo** a `10.10.10.10` (puertos `11000`, `13000`,
  `13002`…).
- `nvidia-smi` muestra el proceso en la 1650.

**PARADA** si la ventana no aparece, si el HUD dice `llvmpipe` o `HD 630`, o si
`35` detecta Internet.

## Fase 5 — Captura en el servidor (recomendada)

En una tercera terminal, **antes de pulsar «entrar»**:

```bash
cd ~/metin2-docs
ssh root@10.10.10.10 \
  "tcpdump -n -tttt -i em0 -c 40 'tcp and host 10.10.10.20'" 2>&1 \
  | tee salidas/2026-11-09-c01-05-servidor.txt
```

Cuando salga `listening on em0`, entra al juego. La captura se corta sola a los
40 paquetes; si no, `Ctrl-C`.

**Resultado esperado:** paquetes `10.10.10.20 > 10.10.10.10.11000` y luego
`10.10.10.10.13002` (el canal). Cero tráfico a otra IP.

## Qué se considera éxito

- El cliente llega al login y se entra al juego.
- El HUD de DXVK muestra **GTX 1650** y `nvidia-smi` ve el proceso.
- La jaula no tiene ruta por defecto, `curl` a Internet falla y `ss` solo
  muestra `10.10.10.10`.
- La captura de FreeBSD ve la conexión del cliente `.20`.

Si se cumple, C01 vale y pasamos a endurecer (usuario `metin2`) y a decidir la
topología definitiva. Si no, el cliente Windows de la VM sigue intacto.

## Si falla

| Síntoma | Qué hacer |
|---|---|
| Aparece un diálogo de **Mono/Gecko** | Cancélalo. El prefijo se creó con `mscoree,mshtml=` desactivados; si vuelve, dime. |
| La ventana no aparece | Comprueba `echo $DISPLAY` y `echo $XAUTHORITY`. Prueba un programa simple dentro de la jaula: `sudo ip netns exec metin2lab sudo -u "$USER" env DISPLAY="$DISPLAY" XAUTHORITY="$XAUTHORITY" wine notepad`. |
| `Failed to initialize Vulkan` | Falta Vulkan de 32 bits: `sudo pacman -S lib32-vulkan-icd-loader lib32-nvidia-utils`. Comprueba `ls /usr/lib32/libvulkan.so*`. |
| El HUD dice `llvmpipe` o `HD 630` | Fuerza la GPU: `DXVK_FILTER_DEVICE_NAME="NVIDIA GeForce GTX 1650" bash tools/c01/30-run-client.sh`. También puedes probar `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/nvidia_icd.json`. |
| Falla por `d3dx9_43.dll` | `WINEPREFIX=~/metin2lab/wine/prefix winetricks -q d3dx9` (esto descarga de Microsoft). |
| Falla por `msvcp140.dll` / `vcruntime140.dll` | `WINEPREFIX=~/metin2lab/wine/prefix winetricks -q vcrun2015`. |
| Se cierra al arrancar | Mira las últimas líneas: `tail -n 60 ~/metin2lab/wine/logs/client-*.log` y pásamelas. |
| No aparece el HUD de DXVK | DXVK no se cargó. Comprueba `ls -l ~/metin2lab/wine/prefix/drive_c/windows/system32/d3d9.dll` y avísame; si el juego corre igual, puede estar usando el `wined3d` de Wine. |
| Pantalla negra o no cambia de resolución | Prueba ventana (`Alt+Enter`) o edita `~/metin2lab/wine/prefix/drive_c/Games/Metin2/metin2.cfg` a `1024x768x32`. |
| El login no conecta | Dentro de la jaula: `sudo ip netns exec metin2lab ping -c2 10.10.10.10`. En FreeBSD: `ssh root@10.10.10.10 "sockstat -4 -l | grep -E '11000|13000'"`. |
| `PELIGRO` en la fase 3 o 4 | Para. La jaula no está bien montada; publica la salida y avisa. |
| El cliente tiene anti-cheat | C01 no es viable con ese binario. Publica la salida y pasamos a Windows nativo. |
| `virbr-lab` no existe | La VM FreeBSD está apagada. Arranca y repite la fase 3. |
| Conflicto de IP `.20` | La VM Windows sigue encendida. Apágala. |

## Limpiar y repetir

```bash
bash tools/c01/90-netns-down.sh
rm -rf ~/metin2lab/wine
```

Eso borra el prefijo y la copia del cliente. Los originales de
`~/metin2lab/tmp4` y el pack de `~/metin2lab/work/b04` no se tocan.

## Nota de seguridad

- La jaula garantiza que el juego **no tiene red hacia Internet**, pero se
  ejecuta con tu mismo usuario: un exploit nativo podría leer archivos tuyos
  con rutas de Linux. Por eso el siguiente paso, si C01 funciona, es el
  usuario `metin2`.
- X11 (tu pantalla) es el punto más flojo de cualquier jaula de escritorio. No
  dejes terminales de root abiertas ni secretos en el portapapeles mientras
  juegas.
- No vuelvas a añadir `Z:` ni ejecutes Wine como root.

## Qué hará el agente con la salida

1. Confirmar si el cliente arranca, si usa la 1650 y si la jaula está limpia.
2. Si funciona: escribir C01-bis (usuario `metin2`) y decidir topología (C02).
3. Si no: analizar el log de Wine y proponer la alternativa (Windows nativo en
   el portátil con el adaptador USB-Ethernet, o passthrough más adelante).
